# 1. Условие задачи

**Вариант 28. Паромная переправа.**

Между двумя берегами реки действует автомобильный паром. Автомобили различных типов прибывают на оба берега и становятся в отдельные очереди. Каждый автомобиль характеризуется уникальным номером, массой и количеством занимаемых мест.

Паром имеет ограничения по грузоподъёмности и числу перевозимых автомобилей. Погрузка производится только у берега и прекращается, если очередной автомобиль не может быть принят без нарушения хотя бы одного ограничения.

Паром может отправляться после полного заполнения, по истечении максимального времени ожидания либо по решению диспетчера, если дальнейшая погрузка невозможна. После завершения погрузки аппарель закрывается, паром пересекает реку и разгружает автомобили. Погрузка и выгрузка во время движения запрещены. После разгрузки паром принимает автомобили, ожидающие на другом берегу.

Может быть предусмотрен приоритет автомобилей экстренных служб. Используемая стратегия не должна приводить к неограниченному ожиданию обычных автомобилей на одном из берегов.

Требуется разработать консольное приложение, моделирующее работу паромной переправы.

**Входные параметры:**  грузоподъёмность парома; максимальное число автомобилей; количество автомобилей на каждом берегу; масса и размер автомобилей; интервалы их прибытия; время погрузки, выгрузки и движения; максимальное время ожидания отправления; стратегия формирования рейса; правила обслуживания приоритетных автомобилей.

**Отображаемые события:**  прибытие автомобилей, формирование очередей, начало и окончание погрузки, отказ в погрузке, отправление, прибытие, выгрузка и текущее заполнение парома.

**Инварианты:**

- грузоподъёмность и вместимость парома не превышаются;
- автомобиль находится на берегу либо на пароме, но не в двух местах одновременно;
- движение начинается только после завершения погрузки и закрытия аппарели;
- погрузка и выгрузка производятся только у соответствующего берега;
- один автомобиль перевозится не более одного раза.

**Завершение:**  моделирование завершается после перевозки всех автомобилей либо после выполнения заданного количества рейсов, либо по прерыванию пользователем, если задан режим неограниченного по времени выполнения. Неперевезённые автомобили должны быть отражены в итоговой статистике.

Паром, диспетчер и автомобили являются самостоятельными участниками модели.

# 2. Сценарий и взаимодействие

За основу взята модель переправы из предыдущих заданий. Правила погрузки, стратегии `fifo` и `lookahead`, ограничения и приоритет экстренных машин сохранены. В новой версии участники общаются по TCP, а время модели и очереди ведёт сервер.

| Участник | Программа | Что делает |
|---|---|---|
| Паром и диспетчер | `server` | Ведёт очереди, выбирает машины для погрузки, выполняет рейсы и проверяет инварианты |
| Левый и правый берег | `shore` | Получает запрос на прибытие, отвечает серверу и показывает события своего берега |
| Наблюдатель | `observer` | Получает состояние при подключении, затем события обоих берегов, рейсы и итоги |

Сервер выбирает моменты прибытия по прежним настройкам. Когда подходит срок, он отправляет нужному берегу строку `?`. Клиент отвечает байтом `A`, после чего сервер создаёт автомобиль с очередным номером и случайными характеристиками. При двух одновременных прибытиях обработка идёт слева направо. Если берег отключится, сервер дождётся его повторного подключения в момент следующего запроса. У берега с нулевым количеством машин клиент не требуется.

Клиент при подключении отправляет один байт роли: `L`, `R` или `O`. Ответы сервера разделяются переводами строки. Сервер обслуживает сокеты через `poll` между тактами и во время ожидания ответов. Для каждого соединения есть свой буфер отправки. Если наблюдатель перестаёт читать и его буфер заполняется, сервер закрывает это соединение, а остальные продолжают получать события.

Для 4–5 баллов запускаются сервер и клиенты берегов. Каждый берег видит свой вывод, а сервер в консоли сообщает о запуске и причине завершения. Для 6–7 баллов запускается отдельный наблюдатель с общей картиной. Для 8 баллов можно запускать несколько наблюдателей одновременно и подключать их заново во время рейса. Новый наблюдатель получает текущий такт, состояние парома, длины очередей, загрузку и число перевозок. Прошлые события повторно не передаются. Одновременно принимается до 64 TCP-соединений, включая клиентов берегов.

# 3. Интерфейс и запуск

Сборка в Linux, в том числе в Ubuntu через WSL:

```bash
make
```

Команды для отдельных терминалов на одном компьютере:

```bash
./server 127.0.0.1 18428 -c tests/basic.cfg
./observer 127.0.0.1 18428
./shore 127.0.0.1 18428 left
./shore 127.0.0.1 18428 right
```

Второй наблюдатель запускается той же командой в ещё одном терминале. Чтобы увидеть события с начала работы, наблюдателей подключают до запуска обоих берегов. Для распределённого запуска серверу задаётся адрес его сетевого интерфейса, а клиентам — доступный адрес сервера и тот же порт. Например, если серверу принадлежит адрес `192.168.1.10`, его указывают вместо `127.0.0.1` во всех командах.

Настройки вместимости, машин, времени и стратегии читаются из прежних файлов `.cfg`. Их можно переопределить параметрами `ключ=значение` после `-c`. Например, `delay_ms=20` ускоряет показ событий, а `max_trips=4` ограничивает число рейсов. Вывод наблюдателя можно сохранить перенаправлением в файл. Параметр сервера `log_path=файл` включает общий журнал на диске, по умолчанию он отключён.

Модель заканчивается после перевозки всех машин, выгрузки в последнем заданном рейсе, достижения `max_time` или по `Ctrl+C`. При завершении сервер отправляет наблюдателям статистику и закрывает сокеты. Клиенты выходят после получения конца потока. Чтобы отключить отдельного наблюдателя, достаточно нажать `Ctrl+C` в его терминале.

# 4. Тестовые наборы и результаты

```bash
make test
```

Скрипт запускает сервер и отдельные TCP-клиенты. Журналы создаются в `logs/`. Прогоны выполнены в Ubuntu WSL на одном компьютере через loopback.

| Набор | Перевезено | Не перевезено | Рейсов |
|---|---:|---:|---:|
| basic | 20 | 0 | 5 |
| lookahead | 30 | 0 | 10 |
| emergency | 40 | 0 | 10 |
| one_side | 9 | 0 | 3 |
| trips_limit | 16 | 64 | 4 |

В `basic` проверено, что события прибытия правого берега не появляются у левого клиента, а полные итоги приходят наблюдателю. В `invalid` сервер отклоняет конфигурацию с кодом 2.

Дополнительно сервер и два клиента берегов запущены без наблюдателя через адрес сетевого интерфейса WSL. При `max_time=12` сервер завершился по лимиту времени, оба клиента получили конец потока и вышли.

В `unlimited` запущены два наблюдателя. Второй был отключён после отправления парома и запущен снова. При повторном подключении он получил строку:

```text
[t=0019] Состояние: в пути, берег: левый, очереди: 1 и 6, рейсов: 1, перевезено: 0. Паром [5/6 авто, 8/8 мест, 9293/12000 кг] #3 #1 #2 #7 #9
```

Затем клиент получил событие прибытия парома. После SIGINT оба активных наблюдателя получили итог со строкой «Причина завершения: прервано пользователем (Ctrl+C)», а программы закрыли соединения.
